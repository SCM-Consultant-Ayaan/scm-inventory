# 예약재고 자동화 (Apps Script)

[예약 재고 관리] 시트의 우선순위, 예약/홀딩 판정, 홀딩→예약 자동 전환, 메일 발주서 자동 등록을 처리합니다.
`RSV_CONFIG.ALLOWED_SPREADSHEET_IDS`에 등록된 시트(기본: 테스트 시트)에서만 동작합니다.

## 설치 (테스트 시트에서 1회)

1. 테스트 시트 → **확장 프로그램 → Apps Script**
2. `Code.gs` 내용을 전부 지우고 이 폴더의 `Code.gs`를 붙여넣기
3. 왼쪽 ⚙️ **프로젝트 설정** → "appsscript.json 매니페스트 파일 표시" 체크 → `appsscript.json`을 이 폴더 내용으로 교체
   (엑셀 첨부를 읽기 위한 Drive 고급 서비스가 켜집니다)
4. `RSV_CONFIG.ATTACHMENT_NAME_PATTERN`(첨부파일명 규칙), 필요하면 `SENDER_FILTER`, `NOTIFY_TO` 수정 후 저장
5. 함수 선택에서 **`rsvSetup`** 실행 → 권한 승인 (시트, Gmail, Drive)
6. 시트를 새로고침하면 상단 메뉴에 **📦 예약재고 자동화** 가 생깁니다

`rsvSetup` 이 하는 일
- M~T 열에 있던 참고 메모(리드타임 표)를 `예약관리_참고메모` 시트로 옮김
- 기존 보조 수식 열을 정리하고, 용도 왼쪽에 업체명(E), N~U 에 우선순위·자동 열 구성 (1차 구조에서 실행하면 업체명만 E 로 이동)
- 드롭다운, 색상 표시, 필터, 틀 고정 설정
- 트리거 설치: 시트 수정 시 즉시 재계산 + 10분마다 (메일 확인 → 재계산)

## [예약 재고 관리] 새 구조

| 열 | 내용 | 구분 |
|---|---|---|
| A~C | 작성 일자, 등록자, 사용 예정일(출고 희망일) | 입력 |
| D | 출고 예정일 (묶음 출고 기준, 출고 전 건만 갱신) | 자동 |
| E | 입고처 | 입력 |
| F | 업체명 (누적 출고량·묶음 기준, 비우면 입고처/용도로 대체) | 입력 |
| G~N | 용도, 제품코드, 상품명, 수량, 재고 분류, 실재고 반영일, 최종 출고 여부, 비고 | 입력 |
| O | 우선순위: 긴급 / 0순위 / 1순위 / 2순위 | 입력 |
| P | 처리 순번 (상품별) | 자동 |
| Q | 판정 ✅ / 🔄 / ⏳ / ⚠ + 📦 묶음 | 자동 |
| R | 지금 가용재고 (앞 순위 차감 후) | 자동 |
| S | 사용예정일까지 확보 가능 수량 | 자동 |
| T | 업체 누적 출고량 | 자동 |
| U | 자동 처리 이력 | 자동 |
| V | 메일키 (숨김) | 자동 |

다른 시트([재고관리], `통합_일평균_산출`, `0513`/`0519` 시트)는 작성일자·사용예정일·제품코드·상품명·수량·재고분류·출고여부 열을
직접 셀 참조로 읽습니다. `rsvSetup`은 열 삽입/삭제로만 구조를 바꾸므로 이 참조가 자동으로 따라갑니다.
열을 손으로 옮기지 말고 `rsvSetup`(메뉴: 초기 설정 / 구조 업데이트)을 실행하세요. 여러 번 실행해도 입력값은 지워지지 않습니다.

## 자동 정렬

재계산 때 [예약 재고 관리] 행을 정렬합니다 (`AUTO_SORT`). 출고 완료 건은 위(기존 순서 유지, `SORT_DONE_FIRST`),
출고 전 건은 **건(업체명+용도)별로 모아** 건 안에서 **예약재고 → 홀딩재고, 각각 상품명 순**, 건끼리는 그 건의 가장 이른 출고 예정일 순. 행 전체가 옮겨지므로 직접 칠한 색도 함께 이동합니다.
- 메뉴 **지금 재계산 + 정렬**, 10분 자동 실행 때 정렬 (마지막 수정 후 `SORT_IDLE_MINUTES`(5분)이 지나야 — 입력 중 행이 움직이지 않게)
- 셀 수정 직후 재계산에서는 정렬하지 않음
- 필터가 걸려 있으면 조건을 기억했다가 정렬 후 그대로 다시 적용
- 다른 시트 수식은 모두 열 전체 범위(`'예약 재고 관리'!J:J` 등)를 참조하므로 정렬해도 영향 없음

## 행 색상

재고 분류(K)에 따라 행 배경색이 바뀝니다 (조건부 서식, `rsvSetup` 이 설치): 예약재고 연초록 · 홀딩재고 연회색 · 출고 완료 진회색.
비고(N, 직접 칠한 강조색 유지)와 판정(Q, 판정별 색 유지)은 제외.

## R·S·T 열 (수식)

스크립트가 재계산 때마다 R~T 에 **시트 수식**을 넣습니다 (셀을 누르면 계산식이 보임, 헤더 메모에 설명).
- **R 지금 가용재고** = [재고관리] 현재고 − 같은 상품의 출고 전 예약재고 합계 (예약재고 행은 처리 순번 P 가 자기 이하인 예약재고까지, 홀딩재고 행은 모든 예약재고)
- **S 사용예정일까지 확보 가능** (홀딩재고 행만) = R − 순번이 앞선 홀딩재고 수량 + [재고관리] 1~3차 입고예정 중 사용 예정일(C) 이전 수량
- **T 업체 누적 출고량** = 같은 업체(F, 없으면 E) 행 중 K=출고 완료 또는 M=O 인 수량 합계

## 동작 규칙

**신규 등록**: 재고 분류(K)를 **비워두면** 자동 판정합니다.
- 지금 가용재고 = 현재고 − 확정 예약재고 − 앞 순위 건
- 가용재고로 출고 가능하면 → `예약재고(현재고 제외)`
- 아니면 → `홀딩재고(추가발주 제외)` 로 지정하고, 입고예정(재고관리 K~P)을 반영해 언제 가능한지 / 사용예정일까지 몇 개 부족한지 표시

**홀딩 → 예약 자동 전환**: 입고예정이 실제 입고되어 현재고가 늘고, 앞 순위 건을 모두 뺀 뒤 가용재고만으로 출고 가능해지면 자동으로 `예약재고`로 바뀝니다 (T열에 이력). 앞 순위 홀딩이 전환되기 전에는 뒷 순위가 먼저 전환되지 않습니다(`STRICT_QUEUE`).

**우선순위** (`RSV_CONFIG.PRIORITY_ORDER`에서 순서 변경 가능)
1. 우선순위 열 **긴급 / 0순위** (올리브영보다 앞)
2. **올리브영** (입고처 = 올리브영, 또는 업체명에 올리브영 포함)
3. 우선순위 열 **1순위 → 2순위**
4. 작성 일자 빠른 순
5. 사용 예정일 빠른 순
6. 업체 누적 출고량 많은 순

이미 확정된 예약재고는 자동으로 빼앗지 않습니다. 상위 순위 건이 부족하면 판정에 "하위 순위 확정예약 N개 점유 중"이 표시되니 필요하면 수동으로 조정하세요.

**출고 완료**: M열 `O` 또는 재고 분류 `출고 완료` → 계산에서 제외.

## 메일 발주서 자동 등록 (회사 표준 PURCHASE ORDER 양식만)

- 10분마다 Gmail 에서 `MAIL_QUERY` + `MAIL_AFTER`(이 날짜 이후 수신분만) 로 검색, 파일명이 `로지킴`으로 시작하는 엑셀만 열어봄 — 괄호 종류 무관 (예: `[로지킴]플루고_PO 26100101_261001.xlsx`, `(로지킴)_BG(CN)_261007_10_261007.xlsx`)
- 업체명(F)은 F열 드롭다운 값으로 자동 변환 (예: `(주)뷰릿지코퍼레이션`→`뷰릿지`, `리호인터내셔널`→`리호`). 못 맞추면 F를 비우고 비고(N)에 원래 업체명을 남김 — 영문명 등은 `RSV_CONFIG.COMPANY_ALIASES` 에 추가
- 내용이 **PURCHASE ORDER 양식**(상단 PO No. · 발주일 · 발주 차수 · 업체명/유통국가, 품목표 품목명 · 총 수량)일 때만 등록. 다른 엑셀은 건너뜀
- 등록 값: 작성일자=메일 수신일, 등록자=메일자동, 입고처=수출, 업체명=Vendor, 용도=`중국 수출 26-8차`(국가 + 연도-차수), 상품명=품목명(재고관리 상품명과 매칭, 바코드 자동), 수량=총 수량(비어 있으면 입수량×박스 수), 비고=`PO No.`, 재고 분류=비움 → 자동 판정
- 품목명이 영문이어도 같은 파일의 **[제품정보] 탭**(SKU CODE · 품목명(국문) · 품목명(영문))으로 국문명으로 바꿔 등록 (품목코드 우선, 그다음 영문명). 원래 영문명은 비고에 `원문:`으로 남김
- 같은 PO No. 는 한 번만 등록 (회신/전달/재발송 무시). 수정된 PO 를 다시 반영하려면 시트에서 기존 행을 지우고 메일의 `예약재고_등록완료` 라벨을 제거
- 성공: `예약재고_등록완료` 라벨 / 실패: `예약재고_등록실패` 라벨 (반복 시도 안 함, 라벨을 지우면 다시 시도). 결과는 `메일수신로그` 시트
- xlsx 는 스크립트가 압축을 풀어 직접 읽음 (Drive API 권한 불필요, 수식은 엑셀에 저장된 계산값). 직접 읽기 실패 시(.xls 등)에만 구글 시트 변환 사용

## 수정 발주서 → 변경요청 (승인 후 반영)

이미 시트에 있는 발주(같은 PO No. 의 메일키, 또는 같은 용도 `중국 수출 26-8차` + 비슷한 업체명 `뷰릿지 ↔ (주)뷰릿지코퍼레이션`)의 발주서가 다시 오면 새로 등록하지 않고 수량을 비교합니다.
- 차이가 없으면 `변경 없음`으로 로그만 남김
- 차이가 있으면 **[변경요청] 시트**에 줄별로 기록(상태 `대기`)하고 슬랙으로 담당자(`CHANGE_NOTIFY_MENTION`)에게 알림
  - `수량변경` · `취소`(0 개 또는 발주서에서 빠짐) · `추가`(새 품목) · `확인필요`(이미 출고 완료됐거나 같은 상품이 여러 행 → 자동 반영 안 함)
- **승인 방법**: 슬랙 알림 스레드에 `승인` / `반려` 답글 (10분 안에 반영, 메뉴 **슬랙 답글 지금 확인**으로 즉시) 또는 [변경요청] 시트 J열에서 `승인`/`반려` 선택 (즉시 반영)
- 승인하면: 수량변경 → J열 수량 수정 + U열 이력, 취소 → 행 삭제, 추가 → 새 행 추가. 결과는 [변경요청] K열과 슬랙 스레드에 남음
- 같은 내용의 변경요청이 이미 대기 중이면 중복으로 만들지 않음
- 상품명·수량을 지운 행에 남은 숨김 메일키(V)는 재계산 때 자동으로 지움
- 메일은 **메시지 단위**로 처리 여부를 기억합니다 (스크립트 속성 `RSV_MAIL_SEEN`, 30일 보관). 처리 라벨이 붙은 스레드에 나중에 온 답장(수정 발주서)도 읽습니다. 라벨은 Gmail 에서 보기 위한 표시

## 슬랙 알림

메일 PO 로 신규 예약 건이 등록되면 건마다 바로 `RSV_CONFIG.SLACK_CHANNEL`(기본 `C08MB21A4DD`) 채널로 PO No.·업체·용도·품목별 수량과 자동 판정 결과(✅ 예약 확정 / ⏳ 홀딩 …)를 보냅니다.
그 알림 **스레드에 "출고완료"(또는 "출고 완료…")라고 답글**을 달면 10분 안에 그 PO 의 행이 K열 `출고 완료`로 바뀌고(U열에 이력), 봇이 스레드에 처리 결과를 답글로 남깁니다. 메뉴 **슬랙 "출고완료" 답글 지금 확인**으로 바로 반영할 수도 있습니다.
이 기능은 봇 토큰(`SLACK_BOT_TOKEN`)과 슬랙 앱의 `channels:history`, `groups:history` 권한이 필요합니다 (권한 추가 후 앱 재설치).

`SLACK_NOTIFY_CONVERSIONS: true` 로 바꾸면 홀딩→예약 자동 전환도 알립니다.

연결 방법 (둘 중 하나, 토큰은 코드가 아니라 **프로젝트 설정 → 스크립트 속성**에 저장)
- **봇 토큰(권장)**: Slack 앱에 `chat:write` 권한 → 워크스페이스에 설치 → `xoxb-…` 토큰을 `SLACK_BOT_TOKEN` 으로 저장 → 채널에서 `/invite @앱이름`
- **Incoming Webhook**: 해당 채널용 웹훅 URL 을 `SLACK_WEBHOOK_URL` 로 저장 (채널은 웹훅 생성 시 고른 채널로 고정)

메뉴 **슬랙 알림 테스트**로 연결을 확인합니다. 전송 실패는 `메일수신로그`에 `[슬랙]` 으로 남고 등록 처리는 계속됩니다.

## 묶음 출고 계획 / 출고 예정 알림

- 재계산할 때마다 출고 예정일(D)을 다시 계산하고 `묶음출고계획` 시트를 다시 만들며, 판정(Q) 끝에 `📦 B03 · 10/15 출고 (5건 묶음)` 를 붙입니다.
  - **출고 예정일 = 사용 예정일(C)**. 이미 지났으면 오늘, 그날까지 재고가 확보되지 않으면 재고 확보일(입고 후 가능일). C 가 비어 있으면 재고 확보일, 그것도 모르면 '미정'
  - 묶음 = 같은 업체 + 같은 출고 예정일 (사용 예정일보다 앞당겨 묶지 않음). 업체: F 업체명 → 비어 있으면 입고처가 수출일 때 용도 첫 단어 → 그 외 입고처
  - 사용 예정일(C)을 고치면 D 와 묶음이 함께 바뀜
- 매일 `SHIP_ALERT_HOUR`(9시)에 출고일이 D-5 / D-3 / 당일인 묶음을 슬랙으로 알림. **주말과 [휴무일] 시트의 날짜에는 보내지 않고**, 그사이에 지나간 알림은 다음 영업일에 합쳐 보냄. [휴무일] 시트는 처음 실행 때 2026~2027 공휴일로 자동 생성되며 회사 휴무일은 A열에 추가 (품목, 수량, 재고 미확보 건 표시). 사용 예정일이 지났는데 출고 완료되지 않은 묶음은 건수만 함께 알림
- 메뉴 **출고 예정 알림 지금 보내기**로 바로 확인 가능. 새 매일 트리거는 **트리거만 다시 설치**(또는 rsvSetup) 실행 시 생성

## 본 시트 적용

본 시트의 Apps Script 프로젝트에는 다른 코드가 이미 있으므로 `Code.gs`를 덮어쓰지 않고 **새 파일**로 추가합니다.

1. 본 시트 → 확장 프로그램 → Apps Script → 파일 옆 **＋ → 스크립트** → 이름 `예약재고` → 이 폴더 `Code.gs` 내용 붙여넣기
2. 프로젝트 설정(⚙) 시간대가 **(GMT+09:00) 서울**인지 확인 (아니면 `rsvSetup`이 멈춤)
3. **`rsvSetup`** 실행 → 권한 승인
4. 테스트 시트에서는 `rsvRemoveTriggers`(또는 예전 이름 `removeTriggers`)로 자동화를 끕니다

모든 함수·변수에 `rsv`/`RSV_` 접두어가 있어 기존 코드와 이름이 겹치지 않고, `onOpen`을 정의하지 않습니다.
메뉴는 `rsvInstallTriggers`가 설치하는 열기 트리거(`rsvOnOpen`)로 붙습니다.

### 사용 예정일 자동 기재 (메일 PO)
- 사용 예정일(C)이 비어 있으면 같은 건(메일 PO: 같은 PO No. / 수기 입력: 같은 업체+용도) 품목을 출고 가능일 기준 `USE_DATE_BUNDLE_DAYS`(10일) 단위로 묶어 자동 기재: 가장 이른 가능일부터 10일 안에 가능한 품목끼리 묶고, 그 묶음에서 가장 늦은 가능일에 함께 출고 (예: 10/10 2종 · 10/23 3종 · 10/30 1종 → 10/10 / 10/30). 이미 적힌 같은 PO 날짜가 가능일~+10일 안이면 그 날짜에 합류. 확보일 미정 품목은 비워 둠. 한 번 적힌 C 는 유지(직접 수정 가능)

### 슬랙 메시지 형식
- 채널에는 요약(헤더)만, 품목별 상세는 그 메시지의 스레드 답글로 (신규 등록 · 변경 요청 · 출고 예정 알림 · 홀딩→예약 전환)

### 보기(정렬) 두 가지
- 메뉴 `보기: 출고일 정렬 (출고 묶음)` — 출고 예정일 → 업체 → 차수(숫자순) → 예약/홀딩 → 상품명. 업체+출고일이 바뀌는 곳에 굵은 선
- 메뉴 `보기: 업체별 정렬 (업체 → 출고일 → 차수)` — 업체(가장 이른 출고일 순) → 출고 예정일 → 차수 → 예약/홀딩 → 상품명. 업체가 바뀌는 곳에 굵은 선
- 마지막으로 고른 방식을 기억해 10분 자동 정렬에도 그대로 적용 (스크립트 속성 RSV_SORT_MODE)

### 출고 가능 일정 파일
- 메뉴 `출고 가능 일정 파일 (업체 선택 → 엑셀)` → 업체 선택 → `.xlsx` 다운로드 (내 Drive 에도 저장)
- [출고 일정 요약] 탭: 출고일 · D-day · 품목 수 · 총 수량 · 출고 차수 / [출고 리스트] 탭: 출고 가능일 · D-day · 제품명 · 수량 · 출고 차수 · 비고, 출고일별 소계
- 같은 출고일·같은 제품은 차수가 달라도 한 줄로 합산(파란 행), 출고 차수 칸에 모든 차수 기재. 비고 칸은 비워 둠(직접 작성)
- 파일명: `업체명_차수들_출고 일정_MMDD` (예: `뷰릿지_6·7·8·10차_출고 일정_1008.xlsx`, 용도에 차수가 없으면 차수 생략)
- 처음 실행할 때 Drive 권한 승인이 한 번 더 뜸 (임시 시트 → 엑셀 변환)

### [재고관리] X열: 권장수량 발주 시 소진 예상일 (1회 설치)
- 편집기에서 `rsvAddRunoutColumn` 한 번 실행 → W열 오른쪽에 X열 삽입 (기존 X 월평균 재고 → Y, Y 2개월치 재고 → Z, 월별 Z~AS → AA~AT 로 이동, 시트 안 참조는 자동 조정)
- X = 오늘 + (미래 재고 R + 권장수량 W) / 일평균 출고량 V (권장수량이 숫자가 아니면 빈칸, 입고 리드타임 미반영)
- 2개월치 재고: 월별 열에서 0 인 달을 빼고 마지막 두 달 합산

### 수기 입력 신규 건 슬랙 알림
- `SLACK_NOTIFY_MANUAL: true` — [예약 재고 관리]에 직접 입력한 출고 전 행(상품명·수량·용도·업체 또는 입고처가 다 채워진 행)을 업체+용도 단위로 묶어 알림 (요약 + 스레드 상세)
- 마지막 수정 후 5분이 지난 10분 자동 실행 때 전송 (입력 중 알림 방지). 보낸 행은 숨김 V열에 `mn:<묶음ID>|<n>#<서명>` 기록
- 스레드에 "출고완료" 답글 → 그 묶음 행들을 출고 완료 처리 (메일 PO 와 동일)
- 처음 실행 때는 기존 수기 행에 표시만 하고 알리지 않음. 행을 복사해 용도·상품명을 바꾸면 새 건으로 알림

### FOC 자동 할당 (메일 PO)
- `FOC_RULES` — 업체(F 드롭다운 값)·적용 시작 차수·비율·후보(우선순위, 상품명 패턴, 단가, 카톤 입수)
- 발주서 공급가액 합계 × 비율 ÷ 단가 → 카톤 단위 내림. 컬러는 [재고관리] 가용재고(H) 최다 SKU(단종·운영 종료 제외). 1순위에 가용재고가 부족하면 다음 순위
- 같은 PO 로 한 행 추가 (비고 `FOC · …`, 메일키 `po:<PO>|foc`) → 예약/홀딩 판정·사용예정일·슬랙(🎁 FOC 표시)·출고완료 답글에 함께 포함. 수정 발주서 비교 대상에서는 제외
- 출고 가능 일정 파일에서는 FOC 를 별도 줄로, 비고 `FOC`
- 뷰릿지: 26-10차부터 5%, 1순위 블러셔(7,000원·250개) / 2순위 립앰플(7,200원·266개)

### [재고관리] 자동 계산 열 100행 확장 (1회 실행)
- 편집기에서 `rsvExtendInventoryArrays` 실행 → V·AA~AT·BA·BB·BC·BD 의 4행 수식(MAP/MAKEARRAY)을 100행까지 확장
- A열 SKU CODE → [상품 마스터 시트] K열 바코드로 바꿔 수불부·통합_일평균_산출을 찾음 (바코드가 없으면 A열 값 그대로, 빈 바코드 오매칭 방지)
- 펼쳐질 자리(5~100행)에 직접 적힌 값·수식은 지우고 로그에 칸 목록을 남김

### 예약·홀딩 재배분 + 출고 확인 (v3)
- 예약·홀딩은 매번 다시 배분: 긴급/0순위 → 사용 예정일 빠른 순 → 1·2순위 → 올리브영 → 등록일. 재고가 모자라면 그 건부터 홀딩(예약→홀딩 자동 전환 포함)
- 사용 예정일 15일 이내 예약: 판정에 `🚚 D-n 출고 임박`, 행 색 진한 초록
- 사용 예정일 +7일까지 출고 완료가 없으면 `확인 필요(출고 미확인)` → 재고 계산에서 제외 (행 유지)
- 출고 경과 알림(매일 9시, 영업일): 올리브영 +1·3·5일 / 그 외 +3·5일, `OVERDUE_MENTIONS` 태그. 스레드 답글 `출고완료` / `출고완료 새틴 250`(그 품목만 실제 수량, 남은 수량은 새 행) / `취소`(발주취소)
- 수불부 자동 출고 완료: SKU별 사용 예정일 ±3일 실제 출고 합계 = 같은 기간 예약 합계(완료 포함)일 때만
- 재고 분류 드롭다운·색은 재계산 때 한 번 자동 갱신 (`RSV_RULES_VERSION`)

## 예약→홀딩 알림창 + 강제예약

- 재계산(메뉴·편집) 때 **예약 → 홀딩**으로 바뀐 건이 생기면 알림창이 바로 뜹니다.
  - 각 건마다 현재고, 앞 순위 예약 후 남은 수량, **부족 수량**, 먼저 배정된 건(최대 3건)을 보여 줍니다.
  - 체크한 건은 **예약 유지**로 돌아갑니다. 이때 K는 예약재고, O는 `강제예약`(📌)이 됩니다.
  - 체크하지 않으면 그대로 홀딩입니다.
- **시간 트리거(10분 주기 등)에서 생긴 변경**은 알림창을 띄울 수 없습니다. 모아 두었다가 다음 편집·메뉴 실행·시트 열기 때 보여 줍니다.
- **`강제예약`**(O 드롭다운)은 재고가 모자라도 예약으로 유지하고, 맨 앞 순위로 배정합니다.
  - 그만큼 [재고관리] 예약차감재고(H)가 마이너스가 되고, 뒤 순위 건은 홀딩됩니다.
  - 판정(Q)에는 `📌 강제 예약 · 현재고보다 n개 초과`로 표시됩니다.
- 강제예약 건이 없으면 예약 합계는 항상 현재고 이하라서 H가 마이너스가 되지 않습니다.

## 출고 확인 필요 알림 — 요약 1건 + 스레드
- 매일 알림 대상(올리브영 +1/3/5일, 그 외 +3/5일)이 여러 건이어도 채널에는 **요약 메시지 1건**만 올라갑니다. 요약에는 번호를 붙인 건별 한 줄 목록이 들어갑니다.
- 건별 품목·수량·수불부 출고량은 스레드에 번호별로 올라갑니다.
- 스레드 답글에는 **번호**를 붙입니다.
  - `1 출고완료` · `2,3 출고완료` · `1~3 출고완료` · `4 취소` · `전체 출고완료`
  - 일부만 출고됐으면 `1 출고완료 새틴 250` 처럼 씁니다.
  - 한 답글에 여러 줄을 쓸 수 있습니다 (`1 출고완료` 다음 줄에 `2 취소`).
- 번호가 없으면 다시 물어봅니다 (스레드에 1건뿐이면 그 건으로 처리).
- 모든 건이 처리되면 스레드에 완료 메시지가 올라갑니다.
- 이전 방식(건별 메시지) 스레드도 그대로 답글로 처리됩니다.

## 입고 지연
- [재고관리] K~P 입고예정은 납기요청일이 지나도 미입고수량이 남아 있으면 계속 표시합니다 (최근 30일까지). 수식은 시트에서 직접 수정합니다.
- 배분에서는 지난 입고예정을 "오늘 이후 입고"로 계산합니다. 홀딩 판정에는 `입고 지연 (예정 M/D 미입고) — 입고되면 출고 가능`으로 표시됩니다.
- 예약은 실제 현재고(F)로만 잡기 때문에, 지연된 입고예정 때문에 예약이 잘못 잡히지는 않습니다.

## 거래명세서 자동 발급
- **언제 발급되나**: 메일로 PO가 등록되면 그 발주서의 단가와 SHIP TO를 숨김 시트 [거래명세서_발급]에 기억합니다.
  - 거래명세서는 **사용 예정일(C) 2일 전(D-2)** 에 만듭니다 (`INVOICE_DAYS_BEFORE`). 한 PO라도 사용 예정일이 다르면 날짜별로 따로 만듭니다.
  - 출고예정일·품목·수량·단가가 바뀌면 같은 파일을 새 내용과 새 이름으로 덮어씁니다. 그래서 링크는 그대로 유지됩니다.
  - 사용 예정일이 바뀌면 이전 파일은 휴지통으로 보내고, 새 날짜의 D-2에 다시 만듭니다.
  - 저장 위치: `00. B2B 발주/<업체 폴더>`
  - 파일명: `발급일_거래명세서_PO No._업체명.xlsx`
- **발급일**: 출고예정일(D)입니다. PO 안에 날짜가 여러 개면 가장 늦은 날을 씁니다 (`INVOICE_DATE_PICK`).
- **공급받는자**: [B2B 거래업체정보]에서 읽습니다. 업체명(F)이 상호와 다르면 `INVOICE_COMPANY_ALIASES`에 추가합니다.
- **과세 구분**: 기본은 영세율입니다. `INVOICE_TAXED`에 넣은 업체만 부가세 10%입니다 (현재 없음). 업체 시트에 `과세구분` 열이 있으면 그 값이 우선합니다.
- **품목**: FOC는 단가 0으로 같은 명세서에 넣습니다. 17줄을 넘으면 줄을 늘립니다. 비고 배송지는 발주서 SHIP TO에서 가져옵니다.
- **다시 발급**: 품목·수량·단가가 바뀌면 파일명에 `_수정`이 붙습니다.
- **링크**: 발급된 파일 링크는 그 PO 행들의 업체명(F) 셀에 걸립니다.
- **메뉴** (✉️ 메일 발주):
  - 📑 거래명세서 지금 발급
  - 📑 선택한 셀의 묶음 거래명세서 발급 — 선택한 행이 속한 PO × 사용 예정일 묶음 전체를 날짜와 상관없이 지금 발급합니다. 거래명세서 기능 전에 등록된 PO는 등록일 앞뒤 메일에서 발주서를 다시 찾아 단가를 가져옵니다.
- **템플릿**: 원본 xlsx(`INVOICE_TEMPLATE_XLSX_ID`)를 처음 한 번 구글 시트로 바꿔 `00. B2B 발주`에 `[자동발급 템플릿] 거래명세서`로 둡니다. 이 파일은 지우지 마세요.
- **출고 차례 번호**: 한 PO가 여러 번 나가면 PO No. 뒤에 `-1`, `-2`, `-3`을 붙입니다. 사용 예정일이 다르거나, 일부만 출고된 뒤 남은 수량이 나중에 나가는 경우입니다.
  - 예: `261105_거래명세서_BG(CN)_261016_11-1_뷰릿지.xlsx`
  - 비고에는 `PO No. …-1 (1차 출고분)`으로 적습니다.
  - 한 번에 다 나가면 번호를 붙이지 않습니다. 나중에 잔여가 생기면 첫 파일을 `-1`로 바꿔 덮어씁니다.
  - 이미 발급된 번호는 그대로 두고, 새 출고분은 날짜 순으로 다음 번호를 받습니다.
- **지난 건**: 사용 예정일이 이미 지난 묶음은 자동 발급·자동 수정을 하지 않습니다. 필요하면 셀을 선택해 직접 발급합니다.
- **수기 건(메일 PO 아님)**: 셀 선택 발급으로 만들 수 있습니다.
  - 묶음은 업체 + 용도(G) + 사용 예정일이고, PO No. 자리에는 용도(G)를 씁니다.
  - 단가와 SHIP TO는 같은 업체가 메일로 보낸 최근 발주서의 같은 상품 값을 씁니다. 기억된 게 모자라면 그 업체의 최근 메일 PO 3건까지 메일에서 다시 읽습니다.
  - 단가를 못 찾은 품목이 있으면 발급하지 않고 알려 줍니다. 비고나 용도에 FOC가 있는 행은 0원입니다.

## 거래명세서 메일 발송 (W·X·Y 열)
- **W 체크박스**를 체크하거나 메뉴 **📧 선택한 셀의 거래명세서 메일 보내기**를 실행하면, 그 행이 속한 묶음의 확인 창이 뜹니다.
  - 확인 창에는 첨부 파일, 받는 사람, 참조, 제목, 본문이 나오고 모두 고칠 수 있습니다. 보내기 전에 한 번 더 묻습니다.
  - 거래명세서가 아직 없으면 먼저 발급합니다.
- **받는 사람**: 메일 PO는 발주 메일에 **전체 답장**하는 게 기본입니다. 제목은 원래 제목(`Re: …`) 그대로 두어 같은 대화로 이어지게 합니다. 발주 메일 ID를 모르는 예전 PO는 등록일 앞뒤 메일에서 찾아 기억합니다. 체크를 풀면 새 메일로 보내고 받는 사람을 고칠 수 있습니다. 수기 건이나 스레드를 모르는 건은 [B2B 거래업체정보]에 적힌 메일 주소를 씁니다.
- **첨부**: 거래명세서 xlsx를 PDF(A4 세로, 폭 맞춤)로 바꿔 첨부합니다. Drive에는 xlsx만 남습니다.
- **취소**: 확인 창에서 취소하거나 아직 안 보낸 행의 W 체크를 직접 풀면, 그 묶음 거래명세서 파일을 휴지통으로 보내고 업체명(F) 링크를 지웁니다. 자동 발급(D-2)은 그 묶음을 다시 만들지 않고, W를 다시 체크하거나 셀 선택 발급을 하면 새로 만듭니다. 이미 보낸 묶음(Y 날짜 있음)은 건드리지 않습니다.
- **보낸 뒤**: 그 묶음의 모든 행에 W ☑ · X 메일 제목 · Y 보낸 날짜를 적습니다. 취소하거나 창을 닫으면 체크가 풀린 채로 남습니다. 이미 보낸 묶음은 확인 창에서 경고합니다.
- **제목·본문 양식**: `INVOICE_MAIL_SUBJECT`, `INVOICE_MAIL_BODY`. 메일은 트리거를 설치한 계정에서 나갑니다.
- **발급 제외 업체**: `INVOICE_EXCLUDE`(기본 올리브영)에 넣은 업체는 거래명세서 발급과 메일 발송 대상에서 빠집니다.

## B2B 거래업체정보 자동 갱신
- 메일 발주서가 등록되거나 변경요청이 생기면, 발주서 상단 정보(업체명, 사업자 등록번호, 담당자, 이메일, 연락처)로 [B2B 거래업체정보]를 갱신합니다.
- **업체 찾기**: 사업자번호(숫자만 비교)로 먼저 찾고, 없으면 상호, 업체명(F), 별칭 순으로 찾습니다.
- **있는 업체**: 담당자·연락처, 이메일이 바뀌었거나 비어 있으면 고치고, `자동 갱신 기록` 열에 이전 값을 남깁니다. 비어 있는 사업자번호도 채웁니다. 대표자·주소·업태는 발주서에 없어서 건드리지 않습니다.
- **없는 업체**: 새 줄로 추가하고 노란색으로 표시합니다. 대표자·주소·업태/종목은 직접 채워야 합니다.
- 발주서에 이메일이 없으면 보낸 사람 주소를 씁니다 (사내 주소는 제외). `이메일`·`자동 갱신 기록` 열이 없으면 만듭니다.
- **업체별 고정 단가** (`INVOICE_PRICE_LIST`): 발주서 단가 대신 이 원화 단가를 씁니다. 예스스타일은 립앰플 12,000원, 블러셔 12,500원, 비비에센스 40ml 18,000원입니다. 목록에 없는 상품은 발주서 단가를 쓰고, 그 값이 외화로 보이면 발급을 보류합니다.
- **답장할 메일 고르기**: 확인 창의 `답장할 메일` 목록에서 고릅니다.
  - 목록에는 발주 메일(📌)과 Gmail 검색 결과(기본: 거래처 메일 주소에서 최근 120일)가 나옵니다. 검색어를 바꿔 `🔍 메일 찾기`를 누르면 다시 찾습니다.
  - 고른 메일 스레드의 마지막 메일에 전체 답장하고, 제목은 `Re: 원래 제목` 그대로입니다. `답장 안 함`을 고르면 새 메일로 보냅니다.
  - 고른 메일은 그 PO의 기본 답장 메일로 기억합니다.

## 변경요청 슬랙 승인 / 반려 버튼
- 변경요청 알림에 **✅ 승인 / ❌ 반려** 버튼이 붙습니다. 누르면 확인 창이 한 번 더 뜨고, 확인하면 버튼이 "⏳ 처리 중"으로 바뀝니다. 몇 초 뒤 시트에 반영되고 메시지가 "✅ 승인 · 반영" 또는 "🚫 반려"로 바뀌며, 결과는 스레드에 남습니다. 스레드에 `승인` / `반려` 답글로 처리하는 방식도 그대로 됩니다.
- **설정 (한 번만)**:
  1. Apps Script → 배포 → 새 배포 → 유형: 웹 앱, 실행: 나, 액세스: 모든 사용자 → 웹 앱 URL 복사
  2. api.slack.com/apps → B2B-PO 앱 → Interactivity & Shortcuts → On → Request URL에 웹 앱 URL → Save
  3. 같은 앱 → Basic Information → App Credentials → Verification Token을 스크립트 속성 `SLACK_VERIFICATION_TOKEN`으로 저장
  4. 이미 올라간 승인 대기 알림은 메뉴 ⚙️ 설정 → "승인 대기 변경요청 알림에 버튼 붙이기"로 버튼을 붙입니다.
- 버튼을 누를 수 있는 사람을 제한하려면 `CHANGE_APPROVERS`에 슬랙 사용자 ID를 넣습니다.
- 코드를 고친 뒤에는 배포 → 배포 관리 → 수정(연필) → 버전: 새 버전으로 다시 배포해야 웹 앱에 반영됩니다.

## 패킹리스트 (메뉴 📦)
- 업체와 출고일(출고 예정일 D)을 고르면 그날 나가는 품목으로 패킹리스트 엑셀을 만듭니다.
  - 열: 출고일 · 제품명 · 수량 · 박스 수량 · 출고 차수 · 비고 · 제품별 소비기한(EXP) · 박스 사이즈 · 박스 번호 · 1박스 중량 · 박스 총중량, 맨 아래 합계 줄
  - 파일명: `MMDD_업체명_PO No._패킹리스트.xlsx` (PO가 여러 개면 `+`로 이음)
  - 내려받고, 업체 폴더(00. B2B 발주)에도 저장합니다.
- 박스 입수량·사이즈·중량은 [상품 마스터 시트]의 아웃박스 정보를 씁니다.
- 소비기한은 [이지어드민 재고_RD] 유통기한 기준이라 실제 출고 로트와 다를 수 있습니다. 연노랑 칸이니 확인 후 고쳐 주세요.
- 박스 번호 머리글자는 `PACKING_BOX_PREFIX`(리호 = L)로 정하고, 없으면 PO No. 첫 영문자를 씁니다.

## 단가 입력 창 / [업체별 단가]
- 거래명세서를 만들 때 발주서에 원화 단가가 없거나(0원·외화) 모르는 상품이 있으면 **단가 입력 창**이 뜹니다. 셀 선택 발급이나 메일 W 체크 때입니다.
- 입력하면 그 PO에 저장하고 바로 발급과 메일 확인으로 이어갑니다.
- "업체별 단가 시트에도 저장"을 체크하면 [업체별 단가] 시트(업체명 · 상품명 · 단가)에 남습니다. 다음에 그 업체 발주서에 단가가 없으면 자동으로 씁니다. 시트에서 직접 고쳐도 됩니다.

## 거래명세서·패킹리스트 저장 폴더 (07_글로벌)

- 저장 위치: `[07_글로벌]/<업체 폴더>/03 발주/[거래유형/]YY년 M월` (출고월 = 명세서 발급일·패킹리스트 출고일 기준, `_발주 폴더 규칙.md` 6차 정리)
  - 업체 폴더: 이름에 업체 키워드가 들어간 폴더 (숫자로 시작하는 정리된 폴더 우선). 키워드는 `DOC_PARTNER_KEYWORDS`
  - 뷰릿지: 용도/PO 의 중국·CN / 말레이시아·MY / 홍콩·HK 로 지역 폴더 → `03 발주/00 발주`
  - 플루고: 용도에 `재고이동` 이 있으면 `재고 이동(발주서)`, 아니면 `사입(발주서)`
  - 오즈코스·아이케이브: `03 발주/발주서`, 청담글로벌: `발주서`
  - 월 폴더가 없으면 새로 만든다. 월 폴더 안에 차수(예 `26-15차`)나 PO 이름이 들어간 폴더가 있으면 그 안에 저장
  - 업체 폴더가 없으면 예전처럼 `[00. B2B 발주]` 폴더에 저장
- 다시 발급(내용 덮어쓰기)된 파일도 위 폴더로 옮겨진다
- 메뉴 `📑 거래명세서 › 📁 발급된 거래명세서를 업체 폴더(03 발주/월)로 옮기기`: 이미 발급된 파일 일괄 이동

## 발주서 메일을 못 찾는 예전 PO

- 셀 선택 발급·메일 보내기에서 메일 PO 의 발주서를 메일에서 못 찾으면 (발주서 통합 전 과거 건 등) 오류 대신 수기 건처럼 발급:
  같은 업체의 최근 발주서 단가·SHIP TO → [업체별 단가] 시트 → 그래도 없는 단가는 단가 입력 창
- 메일 보내기는 원래 발주 메일 스레드가 없으므로 [B2B 거래업체정보] 메일 주소로 새 메일

## 패킹리스트: 상품 단위로 합침

- 같은 출고일·업체의 같은 상품은 차수가 달라도 한 줄 (FOC 는 따로)
- 출고 차수 칸: `중국 수출 26-8차 · 26-12차` 처럼 모아서, 비고에 차수별 수량 (`26-8차 1,596 + 26-12차 532`)

## 패킹리스트 소비기한: 로트 나누기

- 유통기한 빠른 로트부터 출고 수량만큼 채워 적음: `2028.04.13 (170)` 줄바꿈 `2029.10.01 (1,160)` (같은 상품 FOC 줄은 본품 다음 로트부터)
- 로트 정보: `[이지어드민 로트재고]` 시트(설정 `PACKING_LOT_SHEET`, 한 줄 = 한 로트, 머리글에 상품명/바코드/연동코드 · 유통기한 · 정상재고/재고/수량)
  → 없으면 `[이지어드민 재고_RD]` 유통기한 칸의 로트 하나만 알 수 있어서, 모자란 수량은 `다음 로트 확인 필요 (N)` 빨간 글씨
