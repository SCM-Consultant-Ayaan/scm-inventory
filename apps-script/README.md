# 예약재고 자동화 (Apps Script)

[예약 재고 관리] 시트의 우선순위, 예약/홀딩 판정, 홀딩→예약 자동 전환, 메일 발주서 자동 등록을 처리합니다.
`RSV_CONFIG.ALLOWED_SPREADSHEET_IDS`에 등록된 시트(기본: 테스트 시트)에서만 동작합니다.

## 설치 (테스트 시트에서 1회)

1. 테스트 시트 → **확장 프로그램 → Apps Script**
2. `Code.gs` 내용을 전부 지우고 이 폴더의 `Code.gs`를 붙여넣기
3. 왼쪽 ⚙️ **프로젝트 설정** → "appsscript.json 매니페스트 파일 표시" 체크 → `appsscript.json`을 이 폴더 내용으로 교체
   (엑셀 첨부를 읽기 위한 Drive 고급 서비스가 켜집니다)
4. `RSV_CONFIG.ATTACHMENT_NAME_PATTERN`(첨부파일명 규칙), 필요하면 `SENDER_FILTER`, `NOTIFY_TO` 수정 후 저장
5. 함수 선택에서 **`rsvSetup`** 실행 → 권한 승인 (시트, Gmail, Drive)
6. 시트를 새로고침하면 상단 메뉴에 **📦 예약재고 자동화** 가 생깁니다

`rsvSetup` 이 하는 일
- M~T 열에 있던 참고 메모(리드타임 표)를 `예약관리_참고메모` 시트로 옮김
- 기존 보조 수식 열을 정리하고, 용도 왼쪽에 업체명(E), N~U 에 우선순위·자동 열 구성 (1차 구조에서 실행하면 업체명만 E 로 이동)
- 드롭다운, 색상 표시, 필터, 틀 고정 설정
- 트리거 설치: 시트 수정 시 즉시 재계산 + 10분마다 (메일 확인 → 재계산)

## [예약 재고 관리] 새 구조

| 열 | 내용 | 구분 |
|---|---|---|
| A~C | 작성 일자, 등록자, 사용 예정일(출고 희망일) | 입력 |
| D | 출고 예정일 (묶음 출고 기준, 출고 전 건만 갱신) | 자동 |
| E | 입고처 | 입력 |
| F | 업체명 (누적 출고량·묶음 기준, 비우면 입고처/용도로 대체) | 입력 |
| G~N | 용도, 제품코드, 상품명, 수량, 재고 분류, 실재고 반영일, 최종 출고 여부, 비고 | 입력 |
| O | 우선순위: 긴급 / 0순위 / 1순위 / 2순위 | 입력 |
| P | 처리 순번 (상품별) | 자동 |
| Q | 판정 ✅ / 🔄 / ⏳ / ⚠ + 📦 묶음 | 자동 |
| R | 지금 가용재고 (앞 순위 차감 후) | 자동 |
| S | 사용예정일까지 확보 가능 수량 | 자동 |
| T | 업체 누적 출고량 | 자동 |
| U | 자동 처리 이력 | 자동 |
| V | 메일키 (숨김) | 자동 |

다른 시트([재고관리], `통합_일평균_산출`, `0513`/`0519` 시트)는 작성일자·사용예정일·제품코드·상품명·수량·재고분류·출고여부 열을
직접 셀 참조로 읽습니다. `rsvSetup`은 열 삽입/삭제로만 구조를 바꾸므로 이 참조가 자동으로 따라갑니다.
열을 손으로 옮기지 말고 `rsvSetup`(메뉴: 초기 설정 / 구조 업데이트)을 실행하세요. 여러 번 실행해도 입력값은 지워지지 않습니다.

## 자동 정렬

재계산 때 [예약 재고 관리] 행을 정렬합니다 (`AUTO_SORT`). 출고 완료 건은 위(기존 순서 유지, `SORT_DONE_FIRST`),
출고 전 건은 **건(업체명+용도)별로 모아** 건 안에서 **예약재고 → 홀딩재고, 각각 상품명 순**, 건끼리는 그 건의 가장 이른 출고 예정일 순. 행 전체가 옮겨지므로 직접 칠한 색도 함께 이동합니다.
- 메뉴 **지금 재계산 + 정렬**, 10분 자동 실행 때 정렬 (마지막 수정 후 `SORT_IDLE_MINUTES`(5분)이 지나야 — 입력 중 행이 움직이지 않게)
- 셀 수정 직후 재계산에서는 정렬하지 않음
- 필터가 걸려 있으면 조건을 기억했다가 정렬 후 그대로 다시 적용
- 다른 시트 수식은 모두 열 전체 범위(`'예약 재고 관리'!J:J` 등)를 참조하므로 정렬해도 영향 없음

## 행 색상

재고 분류(K)에 따라 행 배경색이 바뀝니다 (조건부 서식, `rsvSetup` 이 설치): 예약재고 연초록 · 홀딩재고 연회색 · 출고 완료 진회색.
비고(N, 직접 칠한 강조색 유지)와 판정(Q, 판정별 색 유지)은 제외.

## R·S·T 열 (수식)

스크립트가 재계산 때마다 R~T 에 **시트 수식**을 넣습니다 (셀을 누르면 계산식이 보임, 헤더 메모에 설명).
- **R 지금 가용재고** = [재고관리] 현재고 − 같은 상품의 출고 전 예약재고 합계 (예약재고 행은 처리 순번 P 가 자기 이하인 예약재고까지, 홀딩재고 행은 모든 예약재고)
- **S 사용예정일까지 확보 가능** (홀딩재고 행만) = R − 순번이 앞선 홀딩재고 수량 + [재고관리] 1~3차 입고예정 중 사용 예정일(C) 이전 수량
- **T 업체 누적 출고량** = 같은 업체(F, 없으면 E) 행 중 K=출고 완료 또는 M=O 인 수량 합계

## 동작 규칙

**신규 등록**: 재고 분류(K)를 **비워두면** 자동 판정합니다.
- 지금 가용재고 = 현재고 − 확정 예약재고 − 앞 순위 건
- 가용재고로 출고 가능하면 → `예약재고(현재고 제외)`
- 아니면 → `홀딩재고(추가발주 제외)` 로 지정하고, 입고예정(재고관리 K~P)을 반영해 언제 가능한지 / 사용예정일까지 몇 개 부족한지 표시

**홀딩 → 예약 자동 전환**: 입고예정이 실제 입고되어 현재고가 늘고, 앞 순위 건을 모두 뺀 뒤 가용재고만으로 출고 가능해지면 자동으로 `예약재고`로 바뀝니다 (T열에 이력). 앞 순위 홀딩이 전환되기 전에는 뒷 순위가 먼저 전환되지 않습니다(`STRICT_QUEUE`).

**우선순위** (`RSV_CONFIG.PRIORITY_ORDER`에서 순서 변경 가능)
1. 우선순위 열 **긴급 / 0순위** (올리브영보다 앞)
2. **올리브영** (입고처 = 올리브영, 또는 업체명에 올리브영 포함)
3. 우선순위 열 **1순위 → 2순위**
4. 작성 일자 빠른 순
5. 사용 예정일 빠른 순
6. 업체 누적 출고량 많은 순

이미 확정된 예약재고는 자동으로 빼앗지 않습니다. 상위 순위 건이 부족하면 판정에 "하위 순위 확정예약 N개 점유 중"이 표시되니 필요하면 수동으로 조정하세요.

**출고 완료**: M열 `O` 또는 재고 분류 `출고 완료` → 계산에서 제외.

## 메일 발주서 자동 등록 (회사 표준 PURCHASE ORDER 양식만)

- 10분마다 Gmail 에서 `MAIL_QUERY` + `MAIL_AFTER`(이 날짜 이후 수신분만) 로 검색, 파일명이 `로지킴`으로 시작하는 엑셀만 열어봄 — 괄호 종류 무관 (예: `[로지킴]플루고_PO 26100101_261001.xlsx`, `(로지킴)_BG(CN)_261007_10_261007.xlsx`)
- 업체명(F)은 F열 드롭다운 값으로 자동 변환 (예: `(주)뷰릿지코퍼레이션`→`뷰릿지`, `리호인터내셔널`→`리호`). 못 맞추면 F를 비우고 비고(N)에 원래 업체명을 남김 — 영문명 등은 `RSV_CONFIG.COMPANY_ALIASES` 에 추가
- 내용이 **PURCHASE ORDER 양식**(상단 PO No. · 발주일 · 발주 차수 · 업체명/유통국가, 품목표 품목명 · 총 수량)일 때만 등록. 다른 엑셀은 건너뜀
- 등록 값: 작성일자=메일 수신일, 등록자=메일자동, 입고처=수출, 업체명=Vendor, 용도=`중국 수출 26-8차`(국가 + 연도-차수), 상품명=품목명(재고관리 상품명과 매칭, 바코드 자동), 수량=총 수량(비어 있으면 입수량×박스 수), 비고=`PO No.`, 재고 분류=비움 → 자동 판정
- 품목명이 영문이어도 같은 파일의 **[제품정보] 탭**(SKU CODE · 품목명(국문) · 품목명(영문))으로 국문명으로 바꿔 등록 (품목코드 우선, 그다음 영문명). 원래 영문명은 비고에 `원문:`으로 남김
- 같은 PO No. 는 한 번만 등록 (회신/전달/재발송 무시). 수정된 PO 를 다시 반영하려면 시트에서 기존 행을 지우고 메일의 `예약재고_등록완료` 라벨을 제거
- 성공: `예약재고_등록완료` 라벨 / 실패: `예약재고_등록실패` 라벨 (반복 시도 안 함, 라벨을 지우면 다시 시도). 결과는 `메일수신로그` 시트
- xlsx 는 스크립트가 압축을 풀어 직접 읽음 (Drive API 권한 불필요, 수식은 엑셀에 저장된 계산값). 직접 읽기 실패 시(.xls 등)에만 구글 시트 변환 사용

## 수정 발주서 → 변경요청 (승인 후 반영)

이미 시트에 있는 발주(같은 PO No. 의 메일키, 또는 같은 용도 `중국 수출 26-8차` + 비슷한 업체명 `뷰릿지 ↔ (주)뷰릿지코퍼레이션`)의 발주서가 다시 오면 새로 등록하지 않고 수량을 비교합니다.
- 차이가 없으면 `변경 없음`으로 로그만 남김
- 차이가 있으면 **[변경요청] 시트**에 줄별로 기록(상태 `대기`)하고 슬랙으로 담당자(`CHANGE_NOTIFY_MENTION`)에게 알림
  - `수량변경` · `취소`(0 개 또는 발주서에서 빠짐) · `추가`(새 품목) · `확인필요`(이미 출고 완료됐거나 같은 상품이 여러 행 → 자동 반영 안 함)
- **승인 방법**: 슬랙 알림 스레드에 `승인` / `반려` 답글 (10분 안에 반영, 메뉴 **슬랙 답글 지금 확인**으로 즉시) 또는 [변경요청] 시트 J열에서 `승인`/`반려` 선택 (즉시 반영)
- 승인하면: 수량변경 → J열 수량 수정 + U열 이력, 취소 → 행 삭제, 추가 → 새 행 추가. 결과는 [변경요청] K열과 슬랙 스레드에 남음
- 같은 내용의 변경요청이 이미 대기 중이면 중복으로 만들지 않음
- 상품명·수량을 지운 행에 남은 숨김 메일키(V)는 재계산 때 자동으로 지움
- 메일은 **메시지 단위**로 처리 여부를 기억합니다 (스크립트 속성 `RSV_MAIL_SEEN`, 30일 보관). 처리 라벨이 붙은 스레드에 나중에 온 답장(수정 발주서)도 읽습니다. 라벨은 Gmail 에서 보기 위한 표시

## 슬랙 알림

메일 PO 로 신규 예약 건이 등록되면 건마다 바로 `RSV_CONFIG.SLACK_CHANNEL`(기본 `C08MB21A4DD`) 채널로 PO No.·업체·용도·품목별 수량과 자동 판정 결과(✅ 예약 확정 / ⏳ 홀딩 …)를 보냅니다.
그 알림 **스레드에 "출고완료"(또는 "출고 완료…")라고 답글**을 달면 10분 안에 그 PO 의 행이 K열 `출고 완료`로 바뀌고(U열에 이력), 봇이 스레드에 처리 결과를 답글로 남깁니다. 메뉴 **슬랙 "출고완료" 답글 지금 확인**으로 바로 반영할 수도 있습니다.
이 기능은 봇 토큰(`SLACK_BOT_TOKEN`)과 슬랙 앱의 `channels:history`, `groups:history` 권한이 필요합니다 (권한 추가 후 앱 재설치).

`SLACK_NOTIFY_CONVERSIONS: true` 로 바꾸면 홀딩→예약 자동 전환도 알립니다.

연결 방법 (둘 중 하나, 토큰은 코드가 아니라 **프로젝트 설정 → 스크립트 속성**에 저장)
- **봇 토큰(권장)**: Slack 앱에 `chat:write` 권한 → 워크스페이스에 설치 → `xoxb-…` 토큰을 `SLACK_BOT_TOKEN` 으로 저장 → 채널에서 `/invite @앱이름`
- **Incoming Webhook**: 해당 채널용 웹훅 URL 을 `SLACK_WEBHOOK_URL` 로 저장 (채널은 웹훅 생성 시 고른 채널로 고정)

메뉴 **슬랙 알림 테스트**로 연결을 확인합니다. 전송 실패는 `메일수신로그`에 `[슬랙]` 으로 남고 등록 처리는 계속됩니다.

## 묶음 출고 계획 / 출고 예정 알림

- 재계산할 때마다 출고 예정일(D)을 다시 계산하고 `묶음출고계획` 시트를 다시 만들며, 판정(Q) 끝에 `📦 B03 · 10/15 출고 (5건 묶음)` 를 붙입니다.
  - **출고 예정일 = 사용 예정일(C)**. 이미 지났으면 오늘, 그날까지 재고가 확보되지 않으면 재고 확보일(입고 후 가능일). C 가 비어 있으면 재고 확보일, 그것도 모르면 '미정'
  - 묶음 = 같은 업체 + 같은 출고 예정일 (사용 예정일보다 앞당겨 묶지 않음). 업체: F 업체명 → 비어 있으면 입고처가 수출일 때 용도 첫 단어 → 그 외 입고처
  - 사용 예정일(C)을 고치면 D 와 묶음이 함께 바뀜
- 매일 `SHIP_ALERT_HOUR`(9시)에 출고일이 D-5 / D-3 / 당일인 묶음을 슬랙으로 알림. **주말과 [휴무일] 시트의 날짜에는 보내지 않고**, 그사이에 지나간 알림은 다음 영업일에 합쳐 보냄. [휴무일] 시트는 처음 실행 때 2026~2027 공휴일로 자동 생성되며 회사 휴무일은 A열에 추가 (품목, 수량, 재고 미확보 건 표시). 사용 예정일이 지났는데 출고 완료되지 않은 묶음은 건수만 함께 알림
- 메뉴 **출고 예정 알림 지금 보내기**로 바로 확인 가능. 새 매일 트리거는 **트리거만 다시 설치**(또는 rsvSetup) 실행 시 생성

## 본 시트 적용

본 시트의 Apps Script 프로젝트에는 다른 코드가 이미 있으므로 `Code.gs`를 덮어쓰지 않고 **새 파일**로 추가합니다.

1. 본 시트 → 확장 프로그램 → Apps Script → 파일 옆 **＋ → 스크립트** → 이름 `예약재고` → 이 폴더 `Code.gs` 내용 붙여넣기
2. 프로젝트 설정(⚙) 시간대가 **(GMT+09:00) 서울**인지 확인 (아니면 `rsvSetup`이 멈춤)
3. **`rsvSetup`** 실행 → 권한 승인
4. 테스트 시트에서는 `rsvRemoveTriggers`(또는 예전 이름 `removeTriggers`)로 자동화를 끕니다

모든 함수·변수에 `rsv`/`RSV_` 접두어가 있어 기존 코드와 이름이 겹치지 않고, `onOpen`을 정의하지 않습니다.
메뉴는 `rsvInstallTriggers`가 설치하는 열기 트리거(`rsvOnOpen`)로 붙습니다.

### 사용 예정일 자동 기재 (메일 PO)
- 메일로 등록된 PO 의 사용 예정일(C)이 비어 있으면 같은 PO 품목을 출고 가능일 기준 `USE_DATE_BUNDLE_DAYS`(10일) 단위로 묶어 자동 기재: 가장 이른 가능일부터 10일 안에 가능한 품목끼리 묶고, 그 묶음에서 가장 늦은 가능일에 함께 출고 (예: 10/10 2종 · 10/23 3종 · 10/30 1종 → 10/10 / 10/30). 이미 적힌 같은 PO 날짜가 가능일~+10일 안이면 그 날짜에 합류. 확보일 미정 품목은 비워 둠. 한 번 적힌 C 는 유지(직접 수정 가능)

### 슬랙 메시지 형식
- 채널에는 요약(헤더)만, 품목별 상세는 그 메시지의 스레드 답글로 (신규 등록 · 변경 요청 · 출고 예정 알림 · 홀딩→예약 전환)

### 보기(정렬) 두 가지
- 메뉴 `보기: 출고일 정렬 (출고 묶음)` — 출고 예정일 → 업체 → 차수(숫자순) → 예약/홀딩 → 상품명. 업체+출고일이 바뀌는 곳에 굵은 선
- 메뉴 `보기: 업체별 정렬 (업체 → 출고일 → 차수)` — 업체(가장 이른 출고일 순) → 출고 예정일 → 차수 → 예약/홀딩 → 상품명. 업체가 바뀌는 곳에 굵은 선
- 마지막으로 고른 방식을 기억해 10분 자동 정렬에도 그대로 적용 (스크립트 속성 RSV_SORT_MODE)

### 출고 가능 일정 파일
- 메뉴 `출고 가능 일정 파일 (업체 선택 → 엑셀)` → 업체 선택 → `.xlsx` 다운로드 (내 Drive 에도 저장)
- [출고 일정 요약] 탭: 출고일 · D-day · 품목 수 · 총 수량 · 출고 차수 / [출고 리스트] 탭: 출고 가능일 · D-day · 제품명 · 수량 · 출고 차수 · 비고, 출고일별 소계
- 같은 출고일·같은 제품은 차수가 달라도 한 줄로 합산(파란 행), 출고 차수 칸에 모든 차수 기재. 비고 칸은 비워 둠(직접 작성)
- 파일명: `업체명_차수들_출고 일정_MMDD` (예: `뷰릿지_6·7·8·10차_출고 일정_1008.xlsx`, 용도에 차수가 없으면 차수 생략)
- 처음 실행할 때 Drive 권한 승인이 한 번 더 뜸 (임시 시트 → 엑셀 변환)

### [재고관리] X열: 권장수량 발주 시 소진 예상일 (1회 설치)
- 편집기에서 `rsvAddRunoutColumn` 한 번 실행 → W열 오른쪽에 X열 삽입 (기존 X 월평균 재고 → Y, Y 2개월치 재고 → Z, 월별 Z~AS → AA~AT 로 이동, 시트 안 참조는 자동 조정)
- X = 오늘 + (미래 재고 R + 권장수량 W) / 일평균 출고량 V (권장수량이 숫자가 아니면 빈칸, 입고 리드타임 미반영)
- 2개월치 재고: 월별 열에서 0 인 달을 빼고 마지막 두 달 합산
